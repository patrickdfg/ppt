# 설교 자막 PPT 제작 (seolgyo-jamak)

주일 설교 원고를 받아 방송/예배용 자막 PPT를 생성한다.
템플릿(`assets/template.pptx`)의 예시 슬라이드를 복제해 텍스트만 교체하므로
배경·폰트·서식이 항상 원본과 동일하게 유지된다.

## 슬라이드 유형 (원고 색상 → 유형 매핑)

| type | 원고 표시 | 화면 | 용도 |
|---|---|---|---|
| `passage` | 본문 `<책 장절>` (서두 '본 문:') | 검정 큰 글씨 + 우하단 노란 장절 | **설교 본문 성구. 맨 앞에 배치.** ref=장절, lines=본문 |
| `cover` | (지난주/오늘 주제) | 녹색 크로마 + 하단 박스 | 날짜 + 설교 제목. 지난주 표지 → 오늘 표지 순 2장 |
| `caption` | **파란색 글자** | 녹색 크로마 + 하단 크림 박스 | 아래자막. 설교자 서술/핵심 문장 |
| `word` | **녹색 글자** 중 하나님·성령 말씀 인용(“ ”) | 예수님 배경, 상단 텍스트 | 말씀 인용. 문장 단위 누적 공개(chunks) |
| `verse` | **녹색/파란 글자** 중 성경 구절 `(요 16:13)` | 흰 액자 배경 | 장절 표기(파란) + 본문. 본문 중 인용된 성구 |
| `emphasis` | 특별히 강조할 짧은 선언 | 흰 배경 큰 글씨 | 삼위체 설명 등 강조 문장 |
| `emphasis2` | 강조(다른 배경) | 별도 배경 큰 글씨 | 심판 선언 등 |
| `notice` | (원고 밖) 광고·공지 | 공지 배경 | 수련회 일정, 예배위원 등. 사용자가 내용 제공 |
| `closing` | (원고 밖) 마무리 | 예배명 + 제목 | 맨 끝. worship=예배명, title=제목 |
| `photo` | (원고 내장 이미지) | 검정 배경 + 사진 1장 꽉 차게 | 원고에 포함된 사진·도표. `image`=파일경로 |

**word 배경(화자)**: `word` 슬라이드는 기본이 예수님 배경이다. 성령님께서 하신 말씀
인용이면 `"speaker": "성령"`을 넣어 `2_성령님말씀` 레이아웃으로 배경을 바꾼다.
이때 슬라이드에 박힌 좌표를 지우고 레이아웃 자리표시자 위치를 상속하므로
왼쪽 성령님 이미지와 글자가 겹치지 않는다. (하나님·예수님 배경 매핑은 아직 없다.
필요하면 build.py의 `SPEAKER_LAYOUT`에 레이아웃 파일명을 추가한다.)

원고에 색 구분이 애매하면 기본은 파란=caption, 녹색=word(인용)·verse(성구)로 본다.
passage(본문 성구)와 notice/closing은 원고 색과 무관한 구조적 유형이다.

**빨간색**: 원고에서 초록/파랑 문장 중 일부 구간만 빨간 글씨인 경우가 있다
(성구 인용문 안에서 핵심 어구만 빨강). 이 경우 해당 유형(word/caption/verse/passage)의
`lines` 안에서 그 구간을 `<r>…</r>`로 감싼다. 감싸지 않은 나머지는 원래 색(검정 계열)으로,
`<r>` 안쪽만 빨간 글씨로 렌더링된다.
예: `"<r>반드시 한 때 두 때 반 때를 지나서</r>"`
`<r>` 태그는 표시되지 않고 사라지며, 실제 PPT에서는 그 구간만 빨간 글씨가 된다.

**파란색**: `<b>…</b>`로 감싼 구간은 파란 글씨(2683C6)가 된다. 슬라이드가 다음 장으로
이어짐을 나타내는 `>>` 표시에 쓴다. 사용법은 `<r>`과 같다.

## 작업 순서

1. **원고 색상 확인**:
   - **hwp/hwpx 파일이면 (가장 정확, 우선 사용)**: 확장자에 따라 도구가 다르다. 출력 형식은 둘이 같다.
     - `.hwpx` (설치 필요 없음, 파이썬 기본 기능만 사용):
       ```bash
       python scripts/hwpx_colors.py 원고.hwpx    # [BLUE]/[GREEN]/[RED]/[BLACK] 라벨로 출력
       ```
       색이 정확히 #0000FF·#008000·#FF0000이 아니어도 가까운 계열로 분류한다.
       어느 계열도 아닌 색은 `[#RRGGBB]`로 나오니, 그 줄은 사용자에게 용도를 확인한다.
     - `.hwp`:
       ```bash
       pip install pyhwp olefile --break-system-packages   # 최초 1회
       hwp5proc xml 원고.hwp > 원고.xml
       python scripts/hwp_colors.py 원고.xml       # [BLUE]/[GREEN]/[RED]/[BLACK] 라벨로 출력
       ```
       pip 설치가 막힌 환경이면 사용자에게 한글에서 `.hwpx`나 PDF로 저장해 달라고 한다.
     이 출력이 곧 슬라이드 배치 근거가 된다. BLACK은 자막에 넣지 않는다.
     RED는 빨간 글씨 구간이며 `<r>…</r>` 마커로 표시해 lines에 반영한다.
   - **원고에 사진/도표가 내장돼 있으면**:
     ```bash
     python scripts/hwpx_images.py 원고.hwpx 이미지폴더   # .hwpx
     python scripts/hwp_images.py 원고.hwp 이미지폴더     # .hwp
     ```
     이미지를 추출하고 각 이미지의 등장 순서·직전 텍스트(맥락)를 출력한다.
     이 맥락으로 어느 위치에 `photo` 슬라이드를 넣을지 판단한다.
     사용자가 "사진도 한 페이지 꽉 차게 넣어줘" 같은 요청을 하면 반드시 이 단계를 수행한다.
   - **PDF만 있으면**: 이미지로 렌더링해 글자 색을 눈으로 확인한다.
     ```bash
     pdftoppm -jpeg -r 100 원고.pdf m && view m-01.jpg ...
     ```
     문서 텍스트 추출본에는 색 정보가 없으므로 이 단계를 건너뛰면 안 된다.
   - 색 구분이 없는 원고(순수 텍스트)라면 사용자에게 어떤 문장을 자막으로 쓸지 확인한다.

2. **spec.json 작성**: 원고 순서대로 슬라이드 목록을 만든다.

   ```json
   {
     "date": "2026년 7월 19일 주일말씀",
     "title": "설교 제목",
     "slides": [
       {"type": "passage", "ref": "마태복음 16장 27절",
        "lines": ["“인자가 아버지의 영광으로 그 천사들과 함께 오리니", "그 때에 각 사람의 행한 대로 갚으리라.”"]},
       {"type": "cover", "date": "2026년 7월 15일 수요말씀", "title": "‘지난 설교 제목’"},
       {"type": "cover", "date": "2026년 7월 19일 주일말씀", "title": "설교 제목"},
       {"type": "word", "speaker": "성령", "chunks": [
         ["“사람의 몸은 습관이 되면 중독된다."],
         ["그럼, 그대로 체질이 되어 뇌가 고정되어 버린다."],
         ["마음도 그같이 된다."]
       ]},
       {"type": "caption", "chunks": [
         ["말씀도 귀하게 보지 않으면 주지를 말아라."],
         ["돼지에게 황금 시계를 주는 격이다."]
       ]},
       {"type": "verse", "ref": "(전 1:2~3)",
        "lines": ["“전도자가 가로되", "헛되고 헛되며 헛되고 헛되니 모든 것이 헛되도다", "자기에게 무엇이 유익한고”"]},
       {"type": "emphasis", "lines": ["하나님은 영의 아버지시고,", "성령님은 영의 어머니 천모이시고,"]},
       {"type": "notice", "lines": ["2026 하계수련회 일정", "- 7월 23일 교역자수련회"]},
       {"type": "closing", "worship": "2026년 7월 22일 수요 예배", "title": "설교 제목"}
     ]
   }
   ```

   - **passage(본문 성구)**: 서두 '본 문:'의 `<책 장 절>` 구절들. 맨 앞에 각각 한 장씩.
     `ref`는 "마태복음 16장 27절"처럼 풀어 쓰고, `lines`는 성구 본문.
   - **notice/closing**: 원고에 없는 광고·마무리 슬라이드. 사용자가 내용을 주면 넣고,
     없으면 넣지 않는다. closing은 `worship`(예배명)과 `title`(제목) 두 필드만 받는다.

   - **`chunks` (권장)**: 청크(문장) 단위 누적 공개. 한 클릭에 한 문장씩 나타나며,
     한 문장이 여러 줄이면 그 줄들이 동시에 나타난다. 각 청크는 줄 목록.
   - `reveal: true` + `lines` → 한 줄씩 누적 (구방식, 특별히 줄 단위 공개가 필요할 때만)
   - slides 안에 `cover` 항목이 있으면 그 순서대로 표지를 만들고 자동 표지는 생략된다.
     서두에서 지난 설교를 언급하면 **지난 설교 표지(따옴표 붙인 제목) → 오늘 표지** 순으로 2장을 넣는다.
   - `ref`는 verse에서 `(전 1:2~3)` 형식, keyverse에서 `잠 13:12` 형식

3. **빌드 및 검증**:
   ```bash
   python scripts/build.py spec.json 날짜_주일_자막.pptx
   python /mnt/skills/public/pptx/scripts/office/validate.py 출력.pptx --original assets/template.pptx
   ```

4. **QA**: markitdown으로 전체 텍스트를 원고와 대조하고(오탈자·누락·순서),
   렌더링해서 텍스트 넘침이 없는지 확인한다. 완료 후 `/mnt/user-data/outputs`로 복사해 전달.

## 줄나눔·분할 규칙 (사용자 확정 규칙)

- **기본은 내용(문장·구·단락) 기준으로 자른다.** 단, 그렇게 잘랐을 때 슬라이드 간
  분량 차이가 너무 크면 분량 기준으로 조정한다.
- **누적 공개는 문장 단위(chunks)**: 한 클릭에 한 문장. 문장이 길어 2줄이면 2줄 동시 등장.
- word: 한 문장 = 한 줄이 기본 (한 줄 최대 ~25자). 길면 의미 호흡에 따라 구 단위로 나눈다
  (예: "그가 보낸 자라면" / "절대신 하나님께"). 한 장 최대 5행(렌더 기준).
  **빈 줄 스페이서는 넣지 않는다.**
- caption: 1~3줄, 줄당 최대 ~30자. 두 문장이면
  ① 원고에서 별개의 파란 구간 → 별도 caption 슬라이드 2장,
  ② 한 파란 구간의 연속 문장 → chunks로 누적 공개. 판단이 애매하면 chunks 사용.
- **caption 4줄 이상은 build.py가 자동으로 쪼갠다** (3줄까지는 한 장 그대로).
  2줄씩 나누고, 마지막에 1줄만 남으면 앞장에 붙여 3줄로 만든다.
  앞장에는 자막 박스 오른쪽 끝에 파란 `>>`가 자동으로 얹혀 다음 장으로 이어짐을 표시한다.
  (크림 박스 오른쪽 끝까지 늘린 오른쪽 정렬 상자를 같은 줄 수로 겹치는 방식이라
  마지막 줄과 같은 높이의 제일 오른쪽에 놓인다. bodyPr는 마스터의 제목 자리표시자에서
  가져와 `anchor="ctr"`를 맞추고 `rIns="0"`만 덮어쓴다. 여백은 `CONT_RIGHT_MARGIN`.)
  예: 4줄 → 2줄+`>>` / 2줄, 5줄 → 2줄+`>>` / 3줄.
  chunks를 쓴 경우에는 문장 중간을 자르지 않고 문장 단위로 페이지를 나눈다.
- **caption 누적 공개 시 앞 줄 위치 고정**: 자막 박스는 세로 가운데 정렬이라 그냥 두면
  1줄만 보이는 앞장의 글자가 다음 장에서 위로 밀려 올라간다. build.py가 앞장에
  보이지 않는 줄(줄바꿈 없는 공백)을 채워 그 장의 최종 줄 수와 맞추므로, 앞장의 1줄이
  다음 장의 첫 줄과 같은 높이에 놓이고 둘째 줄이 그 아래에 새로 나타나는 것처럼 보인다.
  같은 이유로 `>>`는 그 장의 마지막 누적 슬라이드에만 붙는다.
  spec에 직접 `>>`를 적을 필요는 없다.
- verse: 줄당 약 28자, 한 장 최대 8줄. 넘치면 마지막 줄을 `>>`로 끝내고
  다음 verse 슬라이드로 이어서 분할. 이어지는 장에는 ref를 넣지 않는다 (본문만).
- passage: 본문 폰트가 verse보다 커서 **한 장 최대 5줄**. 넘으면 같은 장절 안에서
  여러 장으로 나눈다 (ref는 매 장에 반복해도 무방, 본문이 이어짐이 자연스러우면 유지).
- 원고의 `<영상 1>`, `◎`, `◯`, `▶` 같은 진행 기호는 자막에 넣지 않는다
- 따옴표는 원고의 전각 따옴표(“ ” ‘ ’)를 그대로 유지한다
- 서두의 오늘 주제 언급은 오늘 표지로 갈음하고, 지난 설교 언급은 지난 설교 표지로 만든다

## 주의사항

- 폰트 '마루 부리OTF 굵은'은 샌드박스에 없어 미리보기 렌더링이 대체 폰트로
  보인다. 사용자 PC에서는 정상 표시되므로 미리보기의 폰트 모양은 무시하고
  위치·분량·넘침만 확인한다.
- 템플릿을 직접 수정하지 말 것. 새 배경/유형이 필요하면 사용자가 준 새 PPT에서
  예시 슬라이드를 추출해 template.pptx를 갱신하고 build.py의 EXEMPLAR를 수정한다.
  (현재 template.pptx는 사용자가 최종 확정한 260722 파일의 9개 유형 예시로 구성됨)
- template.pptx는 슬림본이다. 쓰지 않던 슬라이드 마스터 1·2·4와 거기 딸린
  레이아웃 75개·테마 3개를 걷어내고 배경 이미지를 1600px·무손실로 재압축해
  14.8MB에서 10.6MB로 줄였다. 자막에 쓰는 레이아웃은 전부 마스터 3 소속이라
  렌더 결과는 동일하다(녹색 크로마 슬라이드는 픽셀 차이 0).
  마스터 1·2·4의 레이아웃이 필요해지면 원본 260722 파일에서 가져와야 한다.
- word/emphasis 계열 한 장 최대 5줄, caption 최대 3줄(4줄 이상은 자동 분할),
  verse/passage 최대 8줄. 누적(chunks) 최종 합이 이를 넘으면 여러 장으로 나눈다.
- 완성본 파일명 관례: `YYMMDD_주일_자막.pptx` (예: 260719_주일_자막.pptx)
